# Архитектура и ограничения

```
Windows Electron → HTTPS/Caddy → FastAPI → PostgreSQL
                                  └────→ /data/files/blobs (неизменяемые версии)
```

Сервер рассчитан на общий архив небольшой организации: все активные сотрудники имеют доступ ко всем документам, включая корзину и историю. Права отдельных папок, совместное редактирование одного документа и интеграция с Active Directory в эту версию не входят.

- Пароли: Argon2id. JWT access живёт 15 минут; refresh — 7 дней, с ротацией при использовании. Отзыв сеанса проверяется в БД для каждого запроса. Повторное использование refresh-токена отзывает весь сеанс. Сброс пароля и блокировка пользователя отзывают его сеансы и блокировки файлов.
- Перебор: независимые ограничения неудачных входов по логину и IP в PostgreSQL. Успешный вход не обнуляет IP-счётчик. После лимита нужно дождаться окна `LOGIN_WINDOW_SECONDS`.
- Check-out: сервер выдаёт случайный токен конкретному сеансу входа. Heartbeat продлевает аренду. По истечении аренды другой сотрудник может получить новый токен; старый редактор больше не может сохранять. В дополнение каждое сохранение проверяет `base_version`.
- Изменения дерева и блокировок сериализованы транзакционной advisory-блокировкой PostgreSQL, подходящей для 30 сотрудников. Содержимое загружается и проверяется до короткой транзакции. Каждая версия имеет уникальную пару `(file_id, number)`; чтение использует неизменяемые blobs.
- Сбой между записью blob и коммитом БД может оставить лишний blob, но не повреждает существующую версию. Физическое удаление версий и автоматическая очистка orphan blobs не выполняются. Контролируйте свободное место. Не удаляйте blobs вручную: они могут быть нужны корзине, истории и бэкапам.
- Бэкап: сначала согласованный `pg_dump`, затем файлы. Все blobs, на которые ссылается снимок БД, уже записаны и остаются неизменными. Дополнительные файлы, созданные позже, не мешают восстановлению. Если добавите физическое удаление, этот алгоритм нужно пересмотреть.
- Локальная копия клиента: отдельная случайная папка в `%APPDATA%/shared-file-archive-client/edit-cache`. Polling проверяет стабильность сохранения, отправляет снимок и сравнивает SHA-256. Ошибки сети сохраняют копию; потеря блокировки или конфликт останавливают автоматическую загрузку. После перезапуска копии всегда требуют ручного сравнения.
- Полностью надёжно определить закрытие файла в произвольной версии Office нельзя. Общий процесс Word/Excel, AutoSave, надстройки и отпускание файловых дескрипторов мешают этому. Основной путь: сохранить и закрыть документ, затем нажать «Завершить». Необязательное автоматическое завершение действует только после наблюдения исключительной файловой блокировки Windows и её отсутствия 10 секунд; это эвристика, выключенная по умолчанию. Тайм-аут служит для потери клиента/связи, а не для определения закрытия Office.
- Если требуется автоматическое освобождение, гарантированное при любых сценариях Office, используйте веб-редактирование с ONLYOFFICE/Collabora и серверными callback-событиями либо поддерживаемую Office-надстройку. Это другая интеграция и отдельное развёртывание.
- Word/Excel должны быть установлены и лицензированы на компьютере. Чтение открывает отдельную локальную копию с атрибутом read-only; «Сохранить как» создаст личный файл и не обновит архив. Локальный файл на компьютере может оставаться старой версией, пока другой сотрудник редактирует серверный документ; перечень обновляется каждые 10 секунд, новые открытия скачивают актуальную версию.
- При неопределённом ответе сервера после сохранения клиент может показать конфликт вместо повторной записи. Сохраните локальную копию и проверьте историю. Это защищает от повторной или ошибочной перезаписи.
- Завершённые рабочие копии хранятся 7 дней и очищаются при следующем входе. Незавершённые/конфликтные копии автоматически не удаляются. Read-only копии находятся в `read-cache`; их можно очистить после закрытия Office. Uninstall не удаляет AppData, чтобы не потерять работу.
- Содержимое проверяется по расширению и структуре ZIP/OLE, размер ограничивается; зашифрованные современные Office-документы не принимаются. Это не антивирус. Старые `.doc/.xls` могут содержать макросы — применяйте защиту Office и антивирус организации; не включайте макросы для незнакомых документов.
- HTTPS обязателен для API и клиента. PostgreSQL и FastAPI не публикуют порты в production Compose. HTTP-порт 80 обслуживает ACME и перенаправление Caddy на HTTPS. Внутри изолированной Docker-сети Caddy обращается к API по HTTP. `forwarded-allow-ips=*` допустим только при этой схеме без публичного доступа к API.
- Схема БД версии 1 создаётся при старте. Для будущих изменений схемы нужны отдельные миграции; `create_all` не обновляет существующие таблицы. Сделайте бэкап перед обновлением серверного кода.
