# Поток

Бесплатное веб-приложение для организации работы небольшой команды, в том числе примерно из 30 участников. Задачи, исполнители и рабочее время находятся в одном пространстве. Интерфейс на русском языке, адаптирован для компьютеров и телефонов. Данные сохраняются в SQLite на вашем сервере; подписки и внешняя облачная база не нужны.

## Возможности

- Личные учетные записи, вход по электронной почте и паролю, роли администратора и сотрудника.
- Проекты, задачи и вложенные подзадачи; несколько исполнителей у каждой задачи.
- Канбан и список задач, поиск, фильтры, приоритеты, сроки и статусы.
- Процент выполнения: у обычной задачи задается вручную, у задачи с подзадачами рассчитывается по их прогрессу.
- Персональный таймер и ручное добавление рабочего времени. Таймер сохраняется при обновлении страницы и перезапуске приложения.
- Учет времени по сотрудникам и задачам, фильтры и экспорт CSV.
- Обзор проектов, активности команды и своей работы.
- Управление участниками, отключение учетных записей, изменение профиля и пароля.
- Отдельный демонстрационный режим с 30 участниками и примерами проектов.

Администратор управляет всеми задачами и учетными записями. Сотрудник редактирует созданные им или назначенные ему задачи и ведет свой учет времени. Все участники работают в одном общем пространстве; отдельные организации и приватные проекты в этой версии не реализованы. Добавление участника создает учетную запись, а не отправляет письмо: логин и начальный пароль нужно передать сотруднику самостоятельно.

## Быстрый запуск для знакомства

Нужен **Node.js 24 или новее**.

```sh
npm ci --cache /tmp/potok-npm-cache
npm run dev
```

Откройте `http://localhost:5173` и нажмите «Открыть демоверсию» на экране входа. Демо содержит примерные данные; это не рабочие учетные записи вашей команды. Войти также можно по адресу `admin@potok.local` с паролем `PotokDemo2026!`.

В режиме разработки без `.env` запускается демо. Его база — `data/potok-demo.sqlite`. Сервер API слушает порт 3001; Vite — 5173. Демо-доступ предназначен для знакомства, не для хранения рабочих данных.

## Личное рабочее пространство

1. Скопируйте `.env.example` в `.env`.
2. Укажите свою почту в `POTOK_ADMIN_EMAIL` и новый пароль длиной не менее 12 символов в `POTOK_ADMIN_PASSWORD`.
3. Оставьте `POTOK_DEMO_MODE=false`. Используйте новую базу `data/potok.sqlite`.
4. Установите зависимости, соберите приложение и запустите сервер:

```sh
npm ci --cache /tmp/potok-npm-cache
npm run build
npm start
```

Приложение доступно на порту 3001. Войдите с почтой и паролем администратора, указанными в `.env`. В разделе «Команда» создайте учетные записи сотрудников. Затем создайте проекты, задачи и подзадачи, назначьте исполнителей. Участники могут запускать таймер из задачи или раздела учета времени.

Установочный пароль администратора используется при создании новой базы. Для существующей учетной записи изменяйте пароль через профиль или управление участниками. Переменные окружения не служат способом сброса пароля существующей базы.

Для доступа через интернет нужен ваш сервер, домен и HTTPS через обратный прокси, например Caddy или nginx. Направьте прокси на `127.0.0.1:3001`, сохраняйте исходный заголовок `Host` и передавайте `X-Forwarded-Proto`. После включения HTTPS установите `POTOK_SECURE_COOKIE=true` и `POTOK_TRUST_PROXY=1` для одного доверенного прокси. Закройте порт приложения от внешнего доступа, оставив доступ через прокси. Сервисное размещение и домен могут стоить денег; само приложение предоставляется без подписки по лицензии MIT. Не публикуйте демо-базу вместо рабочей.

## Docker

```sh
# Сначала заполните .env по инструкции выше.
docker compose up -d --build
```

Compose привязывает порт к `127.0.0.1:3001` для подключения через локальный обратный прокси. SQLite хранится в постоянном томе `potok-data`. Пересоздание контейнера не удаляет данные; команда `docker compose down -v` удалит том, поэтому ее не следует использовать для обычного обновления. Пример предполагает один экземпляр сервера; не подключайте несколько контейнеров к одному SQLite-файлу по сетевой файловой системе.

## Проверки

```sh
npm run build
npm test
# Браузерные проверки (если Chromium отсутствует, сначала npx playwright install chromium):
npm run test:e2e
```

Сборка проверяет TypeScript и создает `dist/`. Интеграционные тесты используют отдельные временные базы и проверяют доступ, задачи, подзадачи, учет времени и сохранение данных. Рабочая база не используется тестами.

## Резервные копии

```sh
npm run backup
# Для демо:
POTOK_DB_PATH=data/potok-demo.sqlite npm run backup
# Для другой директории резервных копий:
npm run backup -- /path/to/backups
```

Скрипт использует SQLite online backup, поэтому копия согласована даже при работающем сервере. Сохраняйте копии вне сервера. Для восстановления остановите приложение, сохраните текущую базу и ее `-wal`/`-shm` файлы отдельно, восстановите выбранную копию по `POTOK_DB_PATH`, уберите старые журналы именно восстанавливаемой базы и снова запустите сервер. В Docker копирование нужно выполнить в том `potok-data` при остановленном контейнере; не меняйте базу работающего контейнера.

## Структура

`src/` — React-интерфейс; `server/` — Express API и SQLite; `tests/` — интеграционные проверки; `scripts/backup.js` — резервное копирование. Пароли хэшируются с помощью scrypt; сессии хранятся на сервере, идентификатор передается в HttpOnly cookie. Файл `.env`, базы, `node_modules/` и сборка исключены из Git.
