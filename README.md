# PDF Мастер

Автономное приложение для Windows 10/11 x64: **PDF и изображения → DWG, DXF и DOCX**.
Русский интерфейс, пакетная обработка, редактируемый текст и векторные элементы,
распознавание сканов локальной нейросетью и Tesseract, офлайн-перевод RU↔EN.
Версия **0.4.0**.

## Скачать portable

Обновление 0.4.0 распространяется только как portable:

- [Скачать portable для Windows x64](https://github.com/Sh0MeM0/Games/archive/refs/heads/pdfmaster-portable-v0.4.0.zip)

Распакуйте скачанный архив **целиком** и запустите `RESTORE.cmd`. Он соберёт
portable ZIP из частей и проверит SHA-256. Части нужны из-за
ограничения GitHub в 100 МБ на один файл; компилировать программу не требуется.
После сообщения `SUCCESS` распакуйте полученный portable ZIP в новую папку
и откройте `PDFMaster.exe`. Установка не требуется.

При самостоятельной сборке с `--portable-only` файлы создаются в папке `dist`:

- `dist/PDFMaster-Portable-x64.zip` — распакуйте **весь архив** в отдельную папку
  и запустите `PDFMaster.exe`. Переносить один EXE без остальных файлов нельзя.
  Настройки portable хранятся в `PDFMaster.ini` рядом с программой.
- `dist/PDFMaster-Source.zip` — исходный код и инструкции сборки.
- `dist/SHA256SUMS.txt` — контрольные суммы дистрибутивов.

В комплект входят Python, Qt, LibreDWG, Tesseract, языковые данные русского и
английского, нейросетевые модели OCR и перевода, открытые шрифты. Устанавливать
AutoCAD, ODA, Python, OCR или модели отдельно не нужно. Файлы обрабатываются
локально; отправки документов на сервер нет, интернет для работы не нужен.

### Новое в 0.4.0: локальная нейросеть, перекодировка и перевод

**Нейросетевое распознавание (включено по умолчанию, флажок «Нейросетевое
распознавание (ИИ)», в CLI отключается `--no-ai-ocr`).** Используются модели
PaddleOCR в формате ONNX, выполняемые ONNX Runtime на процессоре:

| Этап | Модель | Что даёт |
|---|---|---|
| Поиск строк | PP-OCRv6 det (small) | строки под любым углом: перекошенные сканы, вертикальные и наклонные надписи чертежей |
| Направление строки | ch_ppocr_mobile_v2.0_cls (0°/180°) + чтение вертикальных строк в обе стороны | перевёрнутые надписи |
| Распознавание | PP-OCRv5 eslav (mobile) | русский, белорусский (І, Ў), украинский, латиница, цифры, ⌀ ± ° и др. |
| Проверка | Tesseract `tessdata_best` rus+eng | каждая фраза перечитывается Tesseract со словарём; спорные слова (и/й, е/ё, «Разре3») заменяются |

Распознанный текст сохраняется **фразами** (одна надпись — один объект TEXT /
текстовое поле), с реальным углом поворота и размером по чернилам. Пропущенные
пробелы восстанавливаются по промежуткам в изображении строки, слова со
смешанными латиницей и кириллицей (`Осb`, `pаздел`) приводятся к одному алфавиту.

Дополнительно:

- **Выравнивание по строкам текста**: если на листе нет длинных линий рамки,
  перекос определяется по направлению строк (до ±15°).
- **Перспектива фотографии**: лист, сфотографированный на более тёмном фоне,
  выпрямляется по четырём углам. Сканы с бумагой во весь кадр не изменяются.
- **Ускорение Tesseract**: каждому процессу Tesseract задаётся один поток OpenMP,
  а независимые участки распознаются параллельно несколькими процессами.
  В среде проверки полоса из 10 строк распознавалась 306 с при потоках
  OpenMP по умолчанию и 1,3 с с одним потоком (см. `docs/VALIDATION.md`).
- **Перекодировка текста PDF**: текст, записанный в одной кодировке и прочитанный
  в другой (cp1251↔cp1252, UTF-8↔cp1251/cp1252, KOI8-R, CP866: `Ïðèâåò`,
  `РџСЂРёРІРµС‚`), автоматически перекодируется. Фрагменты без пригодной
  Unicode-карты (символы частной области, управляющие коды) в режиме OCR «авто»
  заменяются распознаванием изображения страницы.

**Офлайн-перевод RU↔EN** (поле «Перевод» или `--translate en|ru`). Модели Argos
Translate 1.9 (Transformer в формате CTranslate2 + SentencePiece) выполняются
собственным модулем на NumPy; на эталонных фразах результат совпадает с
CTranslate2 (см. `docs/VALIDATION.md`), а проприетарные библиотеки Intel из
колеса CTranslate2 в поставку не входят. Перевод медленнее CTranslate2: в
проверке ≈ 0,3–0,5 с на фразу; пиковая память процесса при переводе EN→RU
около 0,9 ГБ, RU→EN — около 0,5 ГБ (модель выгружается после документа). Строки
объединяются в абзацы, абзац переводится целиком и раскладывается обратно по
исходным строкам; надписи на поворотах остаются на месте. Числа, отметки,
обозначения осей и коды (`3600`, `R150`, `Ось А`, `Б-Б`, `ЛМ-1`, `м²`)
сохраняются. Перевод записывается в **отдельные** файлы с суффиксом `(EN)` или
`(RU)`; исходные результаты не меняются. Машинный перевод требует проверки
специалистом: термины чертежей могут переводиться буквально
(например, «Лестница» → «Ladder» вместо «Stairs»).

#### Замеры на синтетических сканах

Шесть изображений с известным текстом (`docs/VALIDATION.md`): R — доля слов
эталона, найденных точно; P — доля распознанных слов, совпавших с эталоном.
Сравнивается путь «только Tesseract» (логика 0.3.0, но с ускорением OpenMP из 0.4.0)
и путь 0.4.0 по умолчанию.

| Изображение | Только Tesseract (R / P) | 0.4.0 (R / P, время) |
|---|---|---|
| Документ 300 dpi, перекос 3,2°, шум | 0,81 / 0,71 | 0,98 / 0,98, 11 с |
| Документ 300 dpi, перекос −6,5°, JPEG q35 | 0,97 / 0,98 | 0,98 / 0,98, 9 с |
| Документ 110 dpi (мелкий текст) | 0,94 / 0,97 | 0,98 / 0,98, 3 с |
| Наклонный шрифт, перспектива, JPEG q45 | 0,87 / 0,77 | 0,98 / 0,98, 11 с |
| Чертёж 300 dpi, надписи под 0°, 90°, 30°, −90° | 0,52 / 0,69 | 0,95 / 0,95, 10 с |
| Чертёж 200 dpi, JPEG q40, шум | не завершено: один участок > 23 мин | 0,95 / 0,95, 14 с |

Оставшиеся ошибки: знак диаметра `Ø` в шрифте osifont читается как `0`
(`Ø25` → `025`); в документах `C20/25` распознаётся кириллической `С`.
Замеры выполнены на одном компьютере (Linux x64, 4 ядра) на синтетических
изображениях; на реальных сканах результат зависит от качества оригинала.
**Рукописный текст на реальных рукописях не проверялся**: PP-OCRv5 обучен
в основном на печатном тексте, поэтому качество рукописи не гарантируется.

### Новое в 0.3.0: JPG, PNG и другие изображения

Поддерживаются следующие растровые форматы:

| Формат | Расширения |
|---|---|
| JPEG | `.jpg`, `.jpeg`, `.jpe`, `.jfif` |
| PNG / APNG | `.png`, `.apng` |
| TIFF | `.tif`, `.tiff` |
| BMP / DIB | `.bmp`, `.dib` |
| WebP, GIF, AVIF | `.webp`, `.gif`, `.avif`, `.avifs` |
| JPEG 2000 | `.jp2`, `.j2k`, `.jpc`, `.jpf`, `.jpx`, `.j2c` |
| PCX, TGA, Netpbm | `.pcx`, `.tga`, `.ppm`, `.pgm`, `.pbm`, `.pnm` |

Формат определяется по содержимому файла. Если расширение ошибочное, но фактический
формат поддерживается, изображение читается с предупреждением. HEIC/HEIF, RAW-фотографии и SVG напрямую
не поддерживаются: предварительно сохраните их в PNG или TIFF без уменьшения.
Декодеры включены в portable; устанавливать дополнительные кодеки не требуется.

По умолчанию включены очистка фона и изолированного шума, выравнивание перекоса
без обрезки краёв, OCR и восстановление линий. Учитывается EXIF-поворот снимков;
прозрачный фон PNG и других форматов накладывается на белый. Очистка и OCR работают
по участкам в исходном разрешении. Прямые и кривые преобразуются в редактируемые
линии и полилинии, распознанные слова — в объекты TEXT. Светлые протяжённые штрихи
проверяются отдельно, чтобы чёрный контур не приводил к потере серой штриховки.
Текстура стены может быть принята за шум; восстановление узора HATCH и архитектурных
объектов из пикселей не выполняется.

В настройках «Изображения и сканы» можно отключить очистку, выравнивание или линии,
а также указать DPI. «Авто» берёт физический DPI из метаданных; если данных нет,
используется 300 DPI с предупреждением. DPI определяет размер листа в миллиметрах,
а масштаб CAD — увеличение до нужных размеров объекта. Скриншот или фотография
не задаёт реальные размеры здания: проверьте известный отрезок и задайте масштаб.
Перспектива фотографий и деформация бумаги автоматически не исправляются.

Все страницы TIFF и выбранные отображаемые кадры GIF/APNG/WebP/AVIF становятся
отдельными страницами, размещёнными рядом в CAD. Время показа анимации не переносится.
Для одного кадра используйте выбор страниц; у APNG отдельное изображение по умолчанию,
если оно есть, считается первой страницей. Исходный файл не изменяется.

Поддерживаются листы до 160 Мп и 40 000 пикселей по стороне. Большие листы требуют
больше памяти и времени. Для векторизации листов больше 100 Мп используется копия
до 100 Мп с предупреждением; OCR и подложка сохраняют исходное разрешение.
Очистка не восстанавливает утраченные штрихи; рукописные, наклонные и повреждённые
надписи могут распознаться неверно. JPEG-сжатие и маленькое разрешение ограничивают
точность контуров. Для работы предпочтительны исходные PNG/TIFF без потерь.

В комплекте по-прежнему 54 файла шрифтов, 18 семейств с кириллицей,
математическими и техническими символами. Список и лицензии находятся в
[assets/fonts/README.md](assets/fonts/README.md). Для русского и английского OCR
используются модели `tessdata_best`. Очищенная подложка сохраняется рядом с DWG
для сверки; текст, мелкие знаки и контрольные размеры нужно проверить вручную.

### Исправления CAD-текста и длительных операций

Текстовые строки PDF сохраняются как редактируемые объекты `TEXT` с исходной
базовой линией, поворотом и длиной. Высота рассчитывается по метрикам выбранного
шрифта: кегль PDF и высота прописной буквы CAD — разные величины.
Устранена ошибка записи `MTEXT` в LibreDWG 0.14, из-за которой высота обнулялась,
а её значение попадало в ширину. Ранее полученные DWG нужно создать заново из PDF.

Лимит в 180 секунд для записи DWG и OCR снят: преобразование выполняется до
завершения или нажатия «Остановить». Во время работы внешнего конвертера каждые
30 секунд появляется сообщение в журнале; отмена завершает активный процесс.

## Как пользоваться

1. Добавьте PDF или изображения кнопкой или перетащите файлы в окно.
2. Выберите папку результата и нужные форматы.
3. При необходимости задайте страницы (`1-3,5`), язык и режим OCR, пароль PDF.
4. Во вкладке «Точность и оформление» задайте масштаб CAD, параметры подготовки
   изображений и замену шрифтов. Восстановление линий изображений включено по умолчанию;
   векторизация сканов внутри PDF включается отдельно.
5. Нажмите «Конвертировать». Проверьте журнал и файл `*.conversion.json` рядом
   с результатом: там перечислены подстановки, ограничения и ошибки.

Исходные PDF и изображения не изменяются. По умолчанию существующие результаты сохраняются:
при повторной обработке создаётся имя с суффиксом `(2)`, `(3)` и т. д. Замена
включается отдельно. Отмена останавливает DWG/OCR-процесс и сохраняет уже готовые
файлы. Пароль PDF не сохраняется в настройках или отчёте.

## Что становится редактируемым

| Исходные данные | DWG / DXF | DOCX |
|---|---|---|
| Векторные линии и контуры | LINE, LWPOLYLINE, SPLINE, HATCH; отдельные слои страниц | Редактируемые фигуры и кривые Word в режиме расположения |
| Текст PDF с корректной кодировкой | TEXT с базовой линией, высотой, длиной строки и поворотом | Редактируемые текстовые поля или обычные абзацы |
| Штриховые линии | Пользовательские типы линий | Штриховые обводки фигур |
| Текст на скане | OCR → TEXT, приблизительные шрифт и метрики | OCR → редактируемый текст |
| Линии на скане | При включённой векторизации — оси линий и полилинии кривых | Те же восстановленные контуры как фигуры |
| Фотографии и оставшиеся растровые детали | Ссылки IMAGE на соседнюю папку изображений | Встроенные растровые изображения |

**DWG — настоящий бинарный файл AutoCAD 2000 (AC1015)**, созданный встроенным
GNU LibreDWG 0.14 с исправлением замедления на больших DXF. Современные CAD-программы обычно читают эту версию; открытие и
редактирование следует проверить в используемой версии AutoCAD или аналога.
DXF доступен как дополнительный обменный формат. PDF и растровые изображения не хранят исходные размеры
DIMENSION, ограничения, блоки, связи и структуру слоёв CAD: они автоматически не
восстанавливаются. Несколько страниц размещаются рядом в пространстве модели.

Единицы CAD — миллиметры. Масштаб `1` соответствует **размеру страницы PDF или изображения по DPI**, а
не обязательно реальному размеру изделия. Например, если отрезок на странице
имеет длину 100 мм, а должен иметь 5000 мм, задайте масштаб `50`. Проверьте
контрольный размер после импорта. Цвета AC1015 приближены к индексной палитре.
Начальная фаза штриха, прозрачность, обрезка и сложное наложение могут отличаться.

Папку вида `document_<идентификатор>_images` нужно переносить вместе с CAD-файлом:
в ней находятся растровые подложки. Слой `PAGE_<номер>_RASTER_REFERENCE` выключен
при наличии распознанного текста, а у самостоятельных изображений — также при
наличии восстановленных линий. Поэтому подложка не перекрывает редактируемые объекты.
Если ничего редактируемого получить не удалось, подложка остаётся видимой. Слой можно включить в CAD для сверки: часть деталей может остаться
только на подложке. Векторизация скана восстанавливает оси штрихов; дуги представлены
приближёнными полилиниями. Размерные цепи и инженерный смысл автоматически не
восстанавливаются. Нераспознанные буквы и остатки шума могут попасть в геометрию. Подозрительные
крупные OCR-слова проверяются по форме штрихов: отклонённые надписи сохраняются
на подложке и в доступной векторизации для ручной сверки.

### Режимы DOCX

- **Сохранить расположение на странице**: редактируемые текстовые поля и
  векторные фигуры VML. Рекомендуется настольный Microsoft Word. Другие редакторы
  могут иначе отображать такие объекты. Листы больше 22 дюймов уменьшаются до
  ограничения Word. Под распознанными буквами на копии скана очищаются области
  цветом окружающего фона; пересекающиеся линии и сложный фон требуют проверки.
- **Обычный текст**: абзацы для удобного редактирования, рисунки отдельно.
  Таблицы, колонки, формулы, оглавления и структура исходного документа не
  восстанавливаются семантически. Исходный скан добавляется отдельно для сверки.

### Шрифты и ГОСТ

В комплект включены **Liberation Sans/Serif/Mono**, **osifont**,
**PT Sans/Serif/Mono, Caption/Narrow**, **DejaVu Sans/Serif/Mono**,
**Noto Sans/Serif/Math/Symbols/Symbols2** с лицензиями.
osifont — открытый технический шрифт; его наличие само по себе не гарантирует
соответствие всем требованиям ГОСТ/ЕСКД. Программа читает установленные и
добавленные пользователем TTF/OTF/TTC и позволяет задавать замену по имени
исходного шрифта, включая правило `*` для всех шрифтов.

Все существующие шрифты включить невозможно: часть коммерческая, часть запрещает
перераспространение, а PDF может содержать лишь неполный набор глифов. Недоступные
шрифты заменяются с предупреждением. Проприетарные шрифты из PDF не извлекаются.
Добавьте лицензированные ГОСТ-шрифты через настройки программы. SHX не является
шрифтом Word; для общего экспорта используйте эквивалентный TTF/OTF.

В выходные DWG/DOCX шрифты не встраиваются. Чтобы результат правильно выглядел
в Word или CAD, установите нужные шрифты на компьютере получателя либо добавьте
их в каталог поиска шрифтов CAD. В папке программы есть `assets/fonts`; в Windows
TTF можно выделить и выбрать «Установить». Названия в отчёте позволяют проверить
замены. Для распознанного текста гарнитура и начертание подбираются приблизительно.

## Командная строка

В Windows используйте `PDFMaster-CLI.exe`:

```powershell
.\PDFMaster-CLI.exe doctor
.\PDFMaster-CLI.exe convert "C:\Чертежи\фасад.png" "C:\Чертежи\план.jpg" -o "C:\Результаты" --formats dwg
.\PDFMaster-CLI.exe convert "C:\Чертежи\план.pdf" -o "C:\Результаты" --formats dwg docx
.\PDFMaster-CLI.exe convert "C:\Чертежи\скан.pdf" -o "C:\Результаты" --formats dwg dxf docx --vectorize-scans --language rus+eng
.\PDFMaster-CLI.exe convert "C:\Чертежи\фото листа.jpg" -o "C:\Результаты" --formats dwg docx --translate en
.\PDFMaster-CLI.exe convert "C:\Чертежи\скан.tif" -o "C:\Результаты" --formats dwg --language rus+eng
.\PDFMaster-CLI.exe convert "C:\Чертежи\листы.tiff" -o "C:\Результаты" --formats dwg docx --pages 1-3 --scan-dpi 400
.\PDFMaster-CLI.exe convert "C:\Документы\текст.pdf" -o "C:\Результаты" --formats docx --docx-mode flow --pages 1-3 --ask-password
```

Дополнительно: `--ocr auto|always|off`, `--scale 50`, `--font-dir <папка>`,
`--font-map <JSON>`, `--overwrite`, `--no-ai-ocr` (только Tesseract, как в 0.3.0),
`--translate en|ru` (дополнительные переведённые копии). `PDFMaster-CLI.exe doctor`
показывает версии ONNX Runtime/SentencePiece и наличие моделей. Пример карты шрифтов:
`{"Arial": "Liberation Sans", "GOST type A": "osifont"}`.
Код возврата: `0` — запрошенные форматы созданы, `1` — есть ошибки отдельных
файлов/форматов, `2` — ошибка параметров. Предупреждения не означают сбой записи.
OCR `always` заменяет исходный текст распознанным; этот режим полезен при
повреждённой кодировке PDF, но шрифт и начертание определяются приблизительно.
OCR `auto` сохраняет исходный текст и дополняет его распознанным без дубликатов.
Для изображений `auto` и `always` запускают OCR; `off` оставляет очистку и
восстановление линий. `--no-scan-cleanup`, `--no-scan-deskew`, `--no-vectorize-images`
отключают соответствующие этапы. Прежний `--no-vectorize-tiff` сохранён как
синоним `--no-vectorize-images`. `--scan-dpi 0` использует метаданные файла.

## Разработка и проверки

Используйте существующий checkout. Облачная задача уже изолирована;
дополнительный Git worktree для установки зависимостей не нужен.
Нужен Python 3.12. Установка Python-зависимостей:

```bash
python3 -m venv .venv
.venv/bin/python -m pip install -r requirements-dev.txt
PYTHONPATH=src .venv/bin/python -m pdf2office gui
```

Для Linux-разработки установите Tesseract с `rus`, `eng`, `osd` и соберите
LibreDWG 0.14. Пути поиска: `vendor/tesseract/tesseract`,
`vendor/libredwg/dxf2dwg`, затем `PATH`. Для DWG также поддерживается переменная
`PDF2OFFICE_DXF2DWG`. `TESSDATA_PREFIX` указывает папку языковых данных; при
наличии `vendor/tesseract/tessdata` программа использует её.

```bash
QT_QPA_PLATFORM=offscreen .venv/bin/python -m pytest -q
.venv/bin/python tests/make_examples.py examples
PYTHONPATH=src .venv/bin/python -m pdf2office convert examples/*.pdf -o /tmp/pdf-master-check --formats dwg dxf docx --vectorize-scans
```

Тесты проверяют геометрию, Unicode, шрифты, OCR, повороты страниц, заливки,
штриховые линии, структуру DOCX, DWG с обратным чтением, обработку ошибок,
сохранность исходников, отмену и работу интерфейса в фоне. Интеграционные тесты
OCR/DWG пропускаются только при отсутствии соответствующих нативных инструментов;
для полной проверки нужны оба. Созданные примеры в `examples` не содержат
сторонних чертежей и подходят для проверки в целевой CAD-программе и Word.
В `examples/results` приложены результаты публичных синтетических PDF, TIFF и
фасада в PNG/JPEG, полученные Windows-версией. Их можно открыть в CAD и Word для проверки.
Результаты `Пример — фасад.*` относятся к PNG, `Пример — фасад (2).*` — к JPEG.

Сборка Windows описана в [docs/PACKAGING.md](docs/PACKAGING.md).
Сведения о фактически выполненных проверках: [docs/VALIDATION.md](docs/VALIDATION.md).
