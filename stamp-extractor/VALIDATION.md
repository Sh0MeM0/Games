Node.js 22.23.4, Chromium из Playwright 1.63.0 (это движок, на котором основан

## Качество: сравнение 3.0 и 4.0

Объект считается найденным, если рамка программы и эталонная рамка того же типа
пересекаются с IoU ≥ 0,3 (сопоставление один к одному). Код: `tests/eval/`.
Версия 3.0 запускалась из коммита `3db527f` в Node.js с её собственным OCR
(Tesseract.js 7.0.0, русская и английская модели) и с теми же параметрами, что
её обработчик. Отличие одно: уменьшение изображения сделано усреднением по
площади вместо canvas.

### Наборы

1. **Синтетический тест**: 120 страниц 1600×1200 из `model/synth.py`, сиды
   900000–900119. При обучении (сиды 1000–63199) и подборе порогов (800000–800059)
   они не использовались. Но это **тот же генератор, что и для обучения**, поэтому
   результат для 4.0 оптимистичен. Объекты, видимые меньше чем на 60 %, не
   считаются ни пропуском, ни ошибкой.
2. **Примеры 3.0**: 10 изображений из `examples/` с разметкой
   `tests/fixtures*/*.json` (14 печатей, 13 подписей). На них настраивалась версия 3.0.
3. **Реальные фото подписей**: набор Ultralytics «signature» (AGPL-3.0,
   `github.com/ultralytics/assets/releases/download/v0.0.0/signature.zip`).
   Это 178 кадров 1920×1080: подпись ручкой на документе, ручка в кадре,
   размытие, цветной свет. Размечены только подписи, печатей на кадрах нет.
   Часть `val` (35 кадров) — тест, часть `train` (143) — только подбор порогов.
   Набор в репозиторий не входит.

Выводы, которые следуют из таблицы, и только они:

- На синтетических документах 4.0 находит больше печатей и подписей при
  значительно меньшем числе ложных объектов.
- На примерах, под которые настраивалась 3.0, 4.0 немного хуже. Две вплотную
  стоящие прямоугольные печати в `failures-rectangular*.png` объединяются в
  один объект.
- **На реальных фото подписей 4.0 не нашла ни одной подписи из 35.** Ложных
  объектов в 5 раз меньше, чем у 3.0: 66 против 338. Модель относит размытый
  крупный текст и петли подписи на этих кадрах к печатям.

Скорость, медианы на одно изображение (Node.js, 1 поток, этот контейнер):
модель 4.0 — 0,63–0,93 с плюс поиск объектов 0,14–0,20 с; OCR 3.0 — 1,1–1,9 с
плюс анализ 1,1–5,0 с. В Chromium через сервер Neutralino интерфейс показал
0,6 с на работу модели для страниц тестов.

## Как подбирались константы

Подбор шёл только на проверочных наборах: синтетика с сидами 800000–800059 и
143 кадра `train` из набора Ultralytics. Качество считалось по F1 с
суммированием TP, FP и FN по обоим наборам. Скрипт: `tests/eval/tune.mjs`.

- Печати: чувствительность 0,5, средняя уверенность ≥ 0,7, объединение частей
  до 1,45 размера. Лучшая комбинация из 18; на проверке 51 из 58 печатей при
  8 ложных на синтетике и 154 ложных на 143 фото.
- Подписи: радиус группировки 11 (рабочие ячейки), остальные значения по
  умолчанию. Лучшая комбинация из 24; на проверке 46 из 87 на синтетике, 0 из
  143 на фото.

Опробовано и отклонено по проверочным данным:

- **Второй проход модели в половинном масштабе** — меньше найденных печатей:
  46 против 51.
- **Обязательная рамка или кольцо у печати** — на фото ложных печатей 147 вместо
  154, но на синтетике теряются настоящие печати.

Правило «у печати должны быть надписи» (не менее 8 мелких отдельных знаков,
иначе объект считается подписью) оставлено. На примерах 3.0 оно исправило
крупную размашистую подпись, которую модель приняла за печать.

## Происхождение модели

Как устроена модель и в каких фазах обучалась, описано в
[model/README.md](model/README.md). Экспорт в ONNX сверен с PyTorch: максимальная
разница логитов 1,43·10⁻⁵ на случайном входе 320×448. Входная нормализация в
Python и JavaScript совпадает с точностью 3·10⁻⁸.

## Чего эти проверки не доказывают

- Реальных сканов белорусских или российских документов с печатями в среде не
  было. Точность на документах пользователя не измерена. Пользовательские
  вложения из прошлых сессий здесь также недоступны.
- Синтетический тест создан тем же генератором, что и обучающие данные.
- На реальных фото крупным планом (размытие, цветной свет, ручка в кадре)
  программа в текущем виде непригодна для автоматического поиска подписей.
  Остаётся ручное выделение рамкой.
- Работа на Windows не проверялась.
