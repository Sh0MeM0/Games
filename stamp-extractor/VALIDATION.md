# Проверки версии 3.0.0 — 15.10.2026

## Что проверяется

Используются настоящий Electron 44.7.0, Node.js 24.19.0, Tesseract.js 7.0.0
с локальными русской и английской моделями и реальное сохранение PNG.
В сценариях интерфейса автоматизирован только системный выбор папки.

- `npm test`: безопасные имена и сохранение без
  перезаписи, OCR и его тайм-ауты, фильтры цветов/фона, поиск рамок и подписей,
  отделение рукописных строк, сохранность букв печати, масштабирование координат,
  восстановление коротких разрывов и приоритет ручной кисти.
- `npm run test:ui`: открытие PNG/JPEG, поиск, фильтры, сравнение с оригиналом,
  ручные рамки, кисти/отмена/повтор, масштабирование и девять отдельных PNG.
- `npm run test:documents`: шесть вариантов документа — PNG, JPEG с шумом/тенью,
  монохромный, с пересечениями, повёрнутый и 3600 × 2800; в каждом ровно две
  печати и две подписи. Отрицательные примеры с чёрным и синим печатным текстом
  не должны создавать объекты. Проверяется экспорт в исходном разрешении.
- `npm run test:failures`: наклонные прямоугольные печати с собственным текстом,
  связанные фоновые рукописные строки, подпись на линиях бланка и печатные обрывки.
  Сравнивается каждый сохранённый объект с независимыми масками видимых штрихов,
  букв, фона и соседних объектов. Отдельно контролируются оставшиеся буквы печати
  в файлах подписей: правильного числа объектов недостаточно.
- Проверка достройки сравнивает реальные изменения пикселей с независимым
  авторским контуром. Проверяются отключение, подсветка, отсутствие подсветки
  в PNG и суффикс `_достроено` только при фактически добавленных пикселях.
- Экспорт должен иметь белый непрозрачный фон, исходник не должен изменяться,
  обработка не должна обращаться к внешним HTTP-сервисам.

## Результаты завершённых проверок

`npm test`: **76 тестов прошли**, без пропусков и отключённых проверок.
`test:ui`, `test:documents` и усиленный `test:failures` прошли на настоящем
Electron из каталога разработки. Служебные тесты Linux используют headless
Ozone и `--no-sandbox`; этот флаг не входит в обычный запуск программы.

На финальном **упакованном Linux-приложении** повторно прошли `test:documents`
и усиленный `test:failures`: ASAR, OCR-worker и модели загружались из сборки.
Метрики сложных примеров совпали с запуском из исходников. Все 16 файлов
приложения внутри ASAR побайтно совпали с текущим проверенным кодом.

Сложный авторский документ дал **две печати и две подписи**. Документ с одними
печатями дал две печати и ноль подписей; оба примера с печатными обрывками —
ноль объектов. Метрики ниже получены через настоящий интерфейс, подготовку
изображения для OCR и экспорт, а не только прямым вызовом алгоритма:

| Объект | Сохранено видимых штрихов | Сохранено видимых букв печати | Осталось фоновой рукописной строки |
| --- | ---: | ---: | ---: |
| Верхняя печать | 95,18% | 95,30% | — |
| Нижняя печать | 93,70% | 95,47% | 0,07% |
| Верхняя подпись | 86,23% | — | 6,75% |
| Нижняя подпись | 92,79% | — | 8,31% |
| Подпись на линиях бланка | 97,47% | — | — |

В верхней подписи не осталось измеряемых чужих печатных букв: **0 из 677**
проверяемых пикселей. В нижней осталось 14 из 2941 (0,48%). Метрики считаются
по независимым маскам, с исключением физически общих пикселей и краёв
антиалиасинга. Это не означает идеального восстановления: длинный разрыв
верхнего росчерка полностью не устранён; часть наложений остаётся неоднозначной.

На подписи с линиями бланка включение достройки добавило **111 пикселей**;
все 111 попали на авторский эталонный штрих с допуском 1 пиксель. Существующие
пиксели при этом не удалялись. Подсветка отсутствует в сохранённых PNG.
Исходные изображения остались побайтно неизменными.

## Происхождение примеров и ограничения

[Основные примеры](tests/fixtures/README.md) и
[воспроизведения ошибок 3.0](tests/fixtures-v3/README.md) созданы программно
с известными масками объектов. Это авторские учебные документы, **не выборка
реальных сканов**. Исходные файлы вложений пользователя не были доступны
локально; проверка авторских аналогов не является проверкой именно его файлов.

Алгоритм использует OCR, цвет и геометрию. Это не обученный универсальный
детектор подписей. Даже после очистки одноцветные наложения могут содержать
остатки чужих штрихов и потерянные части нужных. Достройка выводит предполагаемые
короткие соединения; она не устанавливает истинную форму скрытого штриха,
не перепечатывает буквы печати и не восстанавливает произвольные большие пробелы.
Метрики на этих примерах не являются обещанием точности на любом документе.

## Проверка Windows portable

Сборка из Linux:

```bash
ELECTRON_BUILDER_CACHE=/workspace/.cache/electron-builder npm run dist:win -- \
  --config.win.signAndEditExecutable=false \
  --config.electronDownload.cache=/workspace/.cache/electron
python3 scripts/verify-portable.py
```

Скрипт раскрывает portable NSIS, проверяет внутренний архив `app-64.7z`,
сравнивает весь payload с `win-unpacked`, проверяет Windows x64 PE, исходники
ASAR, локальные OCR-модели/WASM и отсутствие тестов/dev-инструментов в поставке.
Он записывает размер, SHA-256 и фактическое наличие сертификата подписи.

**Не выполнено:** запуск portable launcher на настоящих Windows 10/11,
проверка SmartScreen, флешки, Windows-диалогов и экранов с различным DPI.
Проверка упакованного приложения на Linux и содержимого EXE не заменяет эти
проверки. Подписи Authenticode у этой сборки нет.
