# Картограмма земляных масс для AutoCAD 2021–2026

Модуль AutoCAD (C#, AutoCAD .NET API) для картограммы земляных масс методом квадратов.
Работа идёт поэтапно; **эта версия — 0.1.0, этап 1**: каркас, команды, хранение данных в DWG,
поверхности, точки-блоки и импорт отметок из TEXT/MTEXT с отчётом.

Сетки, отметок в узлах, объёмов и таблиц в этой версии ещё нет (этапы 4–6).

## Установка

1. Закройте все окна AutoCAD.
2. Запустите `releases/KZM-Setup-0.1.0.exe` (нужны права администратора).
   Модуль устанавливается в `C:\Program Files\Autodesk\ApplicationPlugins\Sh0MeM0.Kzm.bundle`,
   так же как «Профиля».
3. Запустите AutoCAD. Появятся верхнее меню **«Картограмма»** и вкладка ленты **«КЗМ»**.
   Если меню не видно — команда `KZM_MENU`.

Установщик не подписан цифровой подписью, поэтому Windows может показать предупреждение SmartScreen.

Удаление: «Параметры Windows → Приложения» или повторный запуск установщика → «Удалить программу».
Чертежи и данные в них при удалении не затрагиваются.

### Какая сборка загружается

AutoCAD сам выбирает сборку по `PackageContents.xml`:

| AutoCAD | Серия | Платформа сборки | Пакет API при сборке |
|---|---|---|---|
| 2021 | R24.0 | .NET Framework 4.8 | AutoCAD.NET 24.0.0 |
| 2022 | R24.1 | .NET Framework 4.8 | AutoCAD.NET 24.1.51000 |
| 2023 | R24.2 | .NET Framework 4.8 | AutoCAD.NET 24.2.0 |
| 2024 | R24.3 | .NET Framework 4.8 | AutoCAD.NET 24.3.0 |
| 2025 | R25.0 | .NET 8 (net8.0-windows) | AutoCAD.NET 25.0.1 |
| 2026 | R25.1 | .NET 8 (net8.0-windows) | AutoCAD.NET 25.1.0 |

Почему так. Пакеты AutoCAD.NET 24.x собраны под .NET Framework (в пакете указано `.NETFramework4.7`),
а пакеты 25.0.1 и 25.1.0 — под `net8.0`. Это видно по описаниям пакетов на nuget.org.
Сборка под 4.8 выбрана потому, что AutoCAD 2021–2024 работают на .NET Framework 4.8.

Для AutoCAD 2025/2026 с обновлением на .NET 10 (пакеты 25.0.2 и 25.1.1 собраны под `net10.0`)
отдельной сборки нет. Что проверено:
- основные сборки AutoCAD в пакете 25.1.1 имеют ту же версию 25.1.0.0, что и в 25.1.0;
- меняется только AdWindows (лента): 5.2.1.1 → 5.4.3.1.

Загрузку в AutoCAD с .NET 10 я **не проверял**.

## Как устроены данные

- **Поверхность** — имя, тип («фактическая» / «проектная») и слой для её точек. Сначала выбирается
  поверхность (а значит, слой), потом создаются точки.
  Слой по умолчанию — `КЗМ_ТОЧКИ_ФАКТ` или `КЗМ_ТОЧКИ_ПРОЕКТ`; вместо него можно указать любой.
- **Точка** — обычный блок `КЗМ_ТОЧКА` (кружок и атрибут `ОТМЕТКА`). Его можно перемещать,
  копировать и удалять обычными командами AutoCAD и ручками.
  Отметку меняют в палитре **«Свойства» (Ctrl+1) → Атрибуты → ОТМЕТКА** или двойным щелчком
  (окно редактирования атрибутов). Модуль читает отметку из атрибута. Точное значение
  (без округления до 2 знаков) хранится в XData блока. Если текст атрибута отличается от
  записанного значения, отметкой считается введённое число.
  Блок вставляется на Z = 0, его Z не используется. Так MOVE с привязкой к объекту на другой высоте
  не меняет отметку.
- Описание поверхностей, настройки и пары близких точек хранятся в словаре чертежа
  `SH0MEM0_KZM` (Xrecord). Всё сохраняется вместе с DWG.
- Каждая команда отменяется одним шагом `U` / `ОТМЕНИТЬ`.

## Команды этапа 1

| Команда | Что делает |
|---|---|
| `KZM_IMPORT` | Импорт отметок из TEXT/MTEXT в поверхность, с отчётом |
| `KZM_SURFACE` | Список поверхностей; новая; текущая; переименовать |
| `KZM_DUPLICATES` | По каждой паре точек ближе допуска: оставить первую, вторую, обе или удалить обе |
| `KZM_REPORT` | Снова открыть отчёт последнего импорта (в пределах сеанса) |
| `KZM_CLEARMARKS` | Удалить пометки проверки со слоя `КЗМ_ПРОВЕРКА` |
| `KZM_SETTINGS` | Настройки чертежа |
| `KZM_MENU` | Восстановить меню и вкладку ленты |
| `KZM_HELP` | Список команд в командной строке |

### KZM_IMPORT по шагам

1. **Настройки.** Если в чертеже не заданы диапазон отметок, масштаб, высота подписи или размер
   знака, откроется окно настроек. Модуль не подставляет эти значения сам.
2. **Поверхность:** номер из списка или «Новая» (имя → тип → слой точек).
3. **Тексты:**
   - «Рамка» — обычный выбор;
   - «Слои» — указать объекты на нужных слоях или ввести имена с `*` и `?`;
   - «Подобные» — указать один текст: берутся все тексты того же типа, слоя, стиля и высоты
     в текущем пространстве.
4. **Откуда XY:**
   - «Вставка» — способ (а): точка вставки текста;
   - «Маркер» — способ (б): указать один образец маркера (POINT, CIRCLE или блок), и модуль
     найдёт все подобные: тот же тип и слой, для блока — то же имя, для круга — тот же радиус.
     Каждой отметке достаётся ближайший маркер в радиусе R.
5. **Спорные** можно разобрать вручную — способ (в): модуль приближает текст и подсвечивает его,
   вы указываете точку с привязками или «Вставка». Если в тексте несколько чисел, сначала нужно
   ввести отметку. Esc отменяет весь импорт; чертёж при этом не меняется.
6. **Запись** одной транзакцией. Затем:
   - итоги в командной строке;
   - окно отчёта (двойной щелчок по строке приближает объект);
   - проблемные объекты остаются выделенными;
   - рядом с ними ставятся пометки на слое `КЗМ_ПРОВЕРКА` (слой красный и не печатается).

Правила разбора текста:
- MTEXT очищается от кодов форматирования, в TEXT убираются коды `%%`.
- Берутся все совпадения с шаблоном. Затем остаются только числа в диапазоне [min…max]:
  - ровно одно — точка принята;
  - ни одного — текст отброшен с причиной (например, «вне диапазона 140,00…160,00: 12»);
  - несколько — точка спорная.
- Запятая и точка как разделитель равноправны. Знак «−» (U+2212) читается как минус.
- В своём шаблоне можно выделить число именованной группой `(?<num>…)`, например
  `Н=(?<num>[0-9]+[.,][0-9]+)`.
- Способ (б) ничего не решает молча, в спорные попадают:
  - нет маркера в радиусе R;
  - два ближайших маркера отличаются по расстоянию не больше чем на допуск совпадения;
  - один маркер ближайший сразу к нескольким отметкам.
- Точки ближе допуска совпадения не отбрасываются: обе создаются, пара записывается в чертёж,
  а решение принимаете вы командой `KZM_DUPLICATES`.
- Повторный импорт того же текста в ту же поверхность пропускается, и это видно в отчёте.

## Настройки (KZM_SETTINGS)

| Параметр | По умолчанию | Откуда значение |
|---|---|---|
| Шаблон числа | `[-+]?[0-9]+(?:[.,][0-9]+)?` | предложен на этапе вопросов, вы согласились |
| Диапазон отметок min…max | пусто — спросит | задаёте вы |
| Радиус поиска маркера R | пусто — спросит при способе (б) | задаёте вы |
| Допуск совпадения точек | 0,01 м | из задания (п. 2.1) |
| Масштаб 1:500 / 1:1000 / 1:2000 | пусто — спросит | задаёте вы |
| Высота подписи отметки, мм на листе | пусто — спросит | задаёте вы |
| Размер знака точки, мм на листе | пусто — спросит | задаёте вы |
| Знаков после запятой | 2 | задание (п. 4) и СТБ 2073-2010, п. 3.15 |

Размеры блока задаются в миллиметрах листа и умножаются на масштаб:
1:500 → 0,5 м на 1 мм, 1:1000 → 1 м, 1:2000 → 2 м.
Если изменить масштаб или размеры в `KZM_SETTINGS`, все точки перестраиваются автоматически.
Ручные смещения подписей при этом сбрасываются.
Сохранение настроек как шаблона по умолчанию — этап 6.

## Сборка из исходников

Нужны .NET SDK 8 (сборка Microsoft, с Windows Desktop SDK), Python 3 и NSIS 3.

```bash
python3 build.py
```

Скрипт выполняет по порядку:
1. проверки пакета (`tests/packaging`);
2. тесты расчётной части (`tests/Kzm.Core.Tests`);
3. шесть сборок `-p:AcYear=2021…2026`;
4. меню `Kzm.cuix` и `PackageContents.xml`;
5. установщик `releases/KZM-Setup-<версия>.exe` и архив bundle.

Сборки AutoCAD API подключаются из NuGet только для компиляции и в установщик не входят.

## Ограничения этой версии

- Работа в AutoCAD в среде разработки не проверялась: там нет Windows и AutoCAD.
  Проверены компиляция всех шести сборок и автоматические тесты расчётной части.
  Порядок проверки в AutoCAD — `VALIDATION.md`.
- В быстрых свойствах (Quick Properties) атрибуты блока могут не отображаться при стандартной
  настройке AutoCAD. Это не проверено. Палитра «Свойства» (Ctrl+1) показывает атрибуты всегда.
- POINT с Z и блоки с атрибутом как источники отметки, ручной ввод `KZM_POINT` и триангуляция
  относятся к этапу 2.
